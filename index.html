Executive Product Verdict: Wealth Advisory Architecture

A Product and Enterprise Margins POV evaluating the frontier landscape for long-running financial wealth workflows.

The "Uncanny Valley" of Foundation Models

For massive async tasks like 50-page Portfolio Audits or Tax Harvesting, choosing a single "Primary Model" is an architectural anti-pattern. If you use a premium monolithic model like Claude Opus 5 (₹2,415/1M out), you destroy your gross margin on trivial tasks like PDF text extraction. If you use a cheap generalist model, you introduce regulatory liability via mathematical hallucinations in tax logic.

Therefore, the official SARVAX routing recommendation is a Two-Stage Hybrid Cascade.

1. The "Brain"

Primary Reasoning Engine
Kimi K3 (Moonshot AI)
  • Role: Final tax math execution, portfolio rebalancing decisions, and strict compliance verification.
  • Why: Unquestioned #1 global rank on TAU Banking (0.3340). You cannot trade 23% accuracy for a cheaper token rate when computing wealth advisory math.
  • Trade-off Managed: Slow throughput (33 tps). Because these are long-running async workflows, UI is not blocked, rendering latency irrelevant.

2. The "Reader"

Heavy-Lift Extraction Engine
DeepSeek V4 Pro
  • Role: OCR parsing, raw data extraction from massive PDFs (10-Ks, IPS), and initial summarization.
  • Why: Operates at a fraction of the cost (₹42.03/1M base, ₹4.20/1M cached). Mathematically irresponsible to use premium models for raw text extraction.
  • Trade-off Managed: Strict 60 RPM API limit. Orchestrated asynchronously via the Batch API queue, preventing HTTP 429 concurrency crashes.
