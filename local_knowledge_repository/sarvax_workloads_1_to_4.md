## 1. Complete Workload Specifications & Token Accounting

Every SARVAX agent request decomposes into distinct token categories across the execution pipeline:
* **LLM Input Context**: Core prompt including client transcripts, portfolio JSON/tables, and system directives.
* **Tool Overhead Tokens**: Schema definitions, function declarations, and API parameters injected into the system prompt.
* **LLM Output Tokens**: Final structured JSON/Markdown response generated for advisors or CRM systems.
* **Reasoning Tokens**: Internal chain-of-thought tokens generated by reasoning engines (billed at output rates).
* **Retrieval (RAG) Context Tokens**: Chunked vector context fetched from vector databases during prefill.
* **Embedding Tokens**: Vector embedding calls for semantic retrieval over client historical records.
* **OCR Tokens**: Multimodal image/PDF tile tokens for statement and policy document ingestion.

## 5. Technical Optimization Opportunities & Architectural Levers

### 1. Reader-Brain Hybrid Cascade Architecture
Rather than executing every step of complex workloads on high-cost reasoning models (`kimi-k3`), SARVAX implements a 2-tier DAG execution pipeline:
* **Tier 1 (Reader Layer - 85% Token Volume)**: Tasks such as transcript parsing, document OCR verification, JSON formatting, and table extraction are routed to `deepseek-v4-pro` ($0.435/1\text{M}$) or `gemini-3-5-flash-lite` ($0.30/1\text{M}$).
* **Tier 2 (Brain Layer - 15% Token Volume)**: High-complexity capital allocation, tax optimization, and regulatory compliance checks cascade to `kimi-k3` ($3.00/1\text{M}$).
* **Impact**: In Workload 2 (*Annual Portfolio Review*), cascading drops the per-run cost from **₹23.58 to ₹15.17**, saving **₹84,152 per month per 10,000 reviews**.

### 2. Prompt Caching & Mutability Prefix Alignment
Prompt caching efficiency depends directly on **Prefix Block Alignment**:
* **Static Context Order**: System directives $\rightarrow$ Tool schemas $\rightarrow$ Long client CRM histories $\rightarrow$ Ephemeral query turns.
* **DeepSeek Radix Tree Hit Discount**: DeepSeek V4 Pro offers a $99.17\%$ discount on prompt cache hits ($0.003625/1\text{M}$ vs $0.435/1\text{M}$). Keeping static client records at the top of the prompt reduces input costs for a 35,000-token client file to **₹0.012 per request**.

### 3. Structural Table & Data Ingestion Tuning
Passing portfolio holdings and insurance schedules as uncompressed raw JSON causes key inflation (`"scheme_name"`, `"nav"`, `"holding_percentage"`) repeated across hundreds of lines.
* **JSON Penalty**: Ingesting financial tables as JSON increases prompt token volume by **$2.1\text{x}$** compared to Markdown/CSV formats.
* **Optimization**: Converting PDF and database tables into Markdown Pipe Tables or TSV prior to LLM prefill reduces prompt input tokens in Workload 2 from 75,000 to 42,000 tokens, achieving an immediate **$44\%$ reduction in prefill billing**.

### 4. Billed Reasoning Token Containment
Reasoning models (`kimi-k3`, `o3-mini`, `deepseek-r1`) generate internal chain-of-thought tokens billed at **Output Token Rates** ($5\text{x} \text{ to } 34\text{x}$ costlier than input tokens).
* In Workload 2, reasoning tokens account for $2,000 \text{ tokens} \times \$15.00/1\text{M} = \mathbf{\$0.030 \text{ per run}}$ (accounting for $12.3\%$ of the total cached run cost).
* Setting `max_reasoning_tokens` caps in API calls prevents stochastic looping on routine portfolio checks, containing output billing spikes.
